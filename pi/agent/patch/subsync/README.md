# subsync —— 订阅地址改写服务

把机场订阅里的 **IP 型节点地址** 自动换成对应**域名**的一个小型常驻服务。解决的具体问题是：

- 机场（订阅服务商）下发的订阅里，节点地址写的是裸 IP
- 机场换 IP 后（通常是因为旧 IP 被墙），手机里存的旧 IP 全部失效，只能重新导入订阅
- 而客户端的「更新订阅」又常因为请求被塞进已经失效的节点而失败（`0 个成功`）

服务做的只有一件事：**拉上游订阅 → 把每个节点的 IP 地址换成域名 → 返回给客户端**。
域名解析结果与原 IP 不一致时不改写（保留原样并在日志里记录），所以不会把能用的配置改成不能用的。

## 为什么域名有效

机场换 IP 时，它自己的域名 DNS 会一起更新（实测某机场的节点域名 TTL 只有 120 秒，明显是为快速换 IP 设计的）。
客户端用域名，IP 怎么换都能靠 DNS 自动跟上，不需要任何重新导入动作。

## 部署形态

- 单文件 Python 3，只用标准库（macOS 自带的 `python3` 即可）
- launchd 常驻：开机自启、崩溃自动拉起
- 只读：不改上游订阅，只做转述
- 两道鉴权：随机令牌路径 + 自定义请求头密钥

## 安装

```bash
./install.sh "<上游订阅链接>" "<监听地址>[,<另一个监听地址>]" [端口]
```

示例（同时监听局域网与 Tailscale，端口 8787）：

```bash
./install.sh "https://example.com/members/getsub.php?service=1&id=abc" "192.168.1.101,100.64.0.5" 8787
```

安装脚本会：

1. 把 `subsync.py` 复制到 `~/.local/lib/subsync/`（生产目录，与源码目录隔离）
2. 首次运行生成 `~/.config/subsync/config.json`（含随机令牌与请求头密钥，权限 600；已存在则不覆盖）
3. 写入 `~/Library/LaunchAgents/net.xhq.subsync.plist` 并加载

## 客户端配置（以 v2rayNG 为例）

订阅分组 → 编辑该订阅：

| 字段 | 填什么 |
|---|---|
| 链接 | `http://<监听地址>:8787/sub/<token>` |
| 请求头 | `X-Sub-Key: <key>` |
| 允许不安全 URL | 打开（用的是 http） |
| 启用自动更新 | 打开，间隔 60 分钟 |

## 关于「监听地址怎么选」

关键约束：**Android 同一时间只允许一个 VPN 应用运行**（官方文档：`VpnService` 参考页）。
所以手机上一个 v2rayNG 和一个 Tailscale 会互相顶掉，不可能同时在线。

推论：

- **局域网地址**（如 `192.168.1.101`）—— v2rayNG 默认路由「绕过大陆和局域网」会把私有 IP 直接放行，
  所以**即使所有节点全挂，订阅请求也能成功**，这是唯一能实现「自动自愈」的地址形态
- **Tailscale 地址**（`100.x.y.z`）—— 传输加密、不进局域网，但要求 Tailscale 处于 VPN 前台，
  此时 v2rayNG 必然断开；只适合「临时在外面手动更新一次」

## 安全模型

| 防护 | 说明 |
|---|---|
| 令牌路径 | `/sub/<32 位随机 hex>`，路径不对统一返回 404（不暴露服务存在） |
| 请求头密钥 | 缺 `X-Sub-Key` 正确值一律 403，即使令牌泄露也用不了 |
| 接口绑定 | 只监听配置里列出的地址，不监听 `0.0.0.0` |
| 只读 | 没有任何写入上游的操作 |

暴露面实话：局域网内主动扫端口能发现该端口开着（返回 404），但拿不到内容；公网无法访问（不做端口映射、不开 UPnP）。
若泄露，损失是节点凭据被蹭流量额度，机场面板重置节点即可止血。

## 接口

| 路径 | 说明 |
|---|---|
| `GET /healthz` | 健康检查，无需鉴权，返回 `ok` |
| `GET /sub/<token>` | 返回改写后的 base64 订阅；需 `X-Sub-Key` 请求头 |
| `GET /sub/<token>?src=<urlencoded url>` | 临时改用别的上游订阅（换机场时不用改配置） |

## 运维

- 日志：`~/Library/Logs/subsync.log`（每次请求一行，含改写统计；不记录令牌与节点凭据）
- 重启：`launchctl kickstart -k gui/$(id -u)/net.xhq.subsync`
- 停止：`launchctl bootout gui/$(id -u)/net.xhq.subsync`
- 改配置后需重启服务生效
- 结果缓存 5 分钟（`cache_ttl`），避免频繁打机场订阅接口
