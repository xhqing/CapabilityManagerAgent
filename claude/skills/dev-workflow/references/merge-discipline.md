# 合并纪律：对齐 main、超集校验、窗口期

本文件是 dev-workflow 第 7 步的完整论证。核心命题：**只要 dev 是 main 的超集（dev ⊇ main），把 dev 合并回 main 后，main 收到的内容就全量等于「在 dev 上跑过全量测试且用户验收过的那份内容」**——合并不引入任何未经测试的变更。整个纪律体系都是为了在合并那一刻保证这个超集关系成立。

## 窗口期的精确定义

**窗口期 = 从「main merge 进 dev」那一刻起，到「dev merge 回 main」那一刻止。窗口内两条都不能违反：**

1. **main 无新提交**：main 被动过（用户手动改、别的分支合回去、测试方同步用例都算），dev 就不再是 main 的超集，merge 回 main 不再是快进——main 上新增的内容没经过测试就混进来了。
2. **dev 无新改动**：merge 回 main 的必须是「跑过全量测试且用户验收过的那个 dev 提交」。测试跑完、验收过后 dev 又 commit 了新东西（哪怕一行），合并进 main 的内容就不等于测试过的内容，保证失效。

**实践口诀：全量测试一绿、用户验收一过，立刻合并，中间不做任何 commit。**窗口期越短越安全；验收可能跨小时甚至隔天，这正是要靠硬校验兜底的原因。

## 硬校验：合并前的必做检查

```bash
git merge-base --is-ancestor main dev && echo "超集成立，可以合并"
```

- 这条命令检查「main 的所有提交都在 dev 里」，即 dev ⊇ main。退出码 0 = 成立。
- **不成立 = main 在窗口期动过** → 必须重新走「merge main 进 dev →（检查本次需求组用例/文档有无变更）→ 重跑全量测试」，然后再校验。
- **纪律 + 校验缺一不可**：纪律（窗口期尽量冻结）降低返工概率，校验（合并前必查）保证「破坏了必然被发现」。只有纪律没有校验，并行场景下保证是空话——因为并行分支天然会互相破坏超集（见下）。

## 快进合并：保证的物理基础

超集成立时，在 main 上 `git merge dev` 自动是**快进合并**（fast-forward）：不产生新的 merge commit，main 的指针直接移到 dev 的最新提交，main 收到的树和 dev 上测试过的树**逐字节相同**。这就是「全量测试通过后合并回 main 才是可靠的」的物理基础——不是流程仪式，是 git 的对象模型保证的等价关系。反过来说，任何打破这层等价的合并方式（测试后 main 上有独立提交、强行非快进合并）都会引入「未经测试的 diff」。

## 并行分支：超集必然被交叉破坏，怎么运转

多个功能分支并行时，**分支 A 合并回 main 这个动作本身就是改 main**，分支 B 的超集当场破坏。这不是谁的错误，是并行的结构性结果。运转方式：

- B 合并回 main 前跑硬校验，发现 main 动过 → 重新 merge main 进 B（此时会带上 A 的成果和可能的冲突）→ 重跑全量 → 再校验。**每一次「重新对齐 + 重测」都覆盖了 main 新进的内容**，超集重新成立后合并依然安全。
- 这正是第 8 步「合并后立即把 main 同步回其它活着的 worktree」的原因：早对齐，冲突小；硬校验是最后的安全网，不是日常手段。

## 窗口期 main 变动后的返工口径

重新对齐、重跑全量、绿了之后，看 main 新进的内容是什么：

- **只是用例或文档**（测试方同步、杂事直改）→ 功能代码没变，用户的验收结论**延续有效**，直接合并；
- **进了别的功能代码** → 用户先前验收时没见过这些代码与本次功能的组合，**请用户快速复验**一遍再合并。

## 「100% 没问题」的精确含义

超集纪律保证的是：**main 收到的内容 == 全量测试通过且用户验收过的那份内容**，即合并这个动作不引入任何未经测试、未经验收的变更。

它**不**保证「软件没有 bug」——测试覆盖度、用例本身的质量是测试方（Hopper）的责任边界；用户验收覆盖不到的维度（没试到的操作路径、环境差异）也可能藏问题。表述时保持这个精确度，避免过度承诺。

## 与全量测试口径的关系（为什么「其它组不阻塞」）

pending 目录里可能同时有多组用例（两个需求并行、一个旧 bug 还没人修）。如果门禁是「全部用例通过」，别组的红用例会让本次**永远无法合并**——流程死锁。所以口径是三段式：`passed/` 全绿（回归防护）+ 本次需求组全绿（增量目标）+ 其它组不阻塞（它们本来就未完成，红着合理）。串行开发、pending 只有一组时，该口径自然退化为「全部通过」。
