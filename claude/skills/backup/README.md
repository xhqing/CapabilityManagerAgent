# backup：多端点备份 skill

把本机不进 git 的私有文件（个人交付物、隐私文档、本机配置等）同时备份到多个互相独立的云端端点，用多端冗余保护文件与信息安全。

## 为什么做多端点备份

**AI 已经渗透到线上工作的方方面面，权限太大了。** Agent 能读写本机文件、能登录并操作云端账户、能执行删除——这带来了前所未有的效率，也意味着前所未有的风险面：一次误操作、一个被误导的指令、一次凭证泄露，就可能让重要文件被删除。如果这些文件只存在一个地方（只在本机、或只在某一个云端），那这一个点被击中，信息就彻底消失、无处找回。

多端备份是对冲这个风险的最直接手段：**把同一份私有文件同时存到多个互相独立的端点**（飞书云盘、其它网盘、WebDAV、S3 等）。攻击或误删要同时命中所有端点，信息才可能真正丢失；端点越多、彼此越独立（不同厂商、不同账号体系），彻底删除的概率就越低。安全上这叫冗余隔离——单点故障不再致命。

这个 skill 就是把上述对策工程化：

- **统一的备份范围（目录制）**：每个项目根一份 `backup/` 目录，放进目录 = 要备份、移出 = 取消，目录即标签，没有清单要维护；只收用户明确点名的文件——复制副本进目录、原文件留原位置，backup/ 永不持有孤本；目录同时区分端点归属——`backup/feishu/` 等与已注册端点同名的子目录只备份到对应端点，根下文件备份到全部端点；
- **可插拔的备份端点（注册制）**：飞书云盘是首个端点，后续可继续注册任意端点——rclone 支持的远端（WebDAV / S3 / Google Drive / Dropbox / OneDrive 等）配好凭证即注册成功，专用端点（如飞书走 lark-cli）加一个脚本分支；
- **端点级备份形态（模式 + 格式白名单）**：每个端点可配 `raw`（原文件直传、云端镜像目录结构，可选 `file_formats` 格式白名单过滤——飞书当前只收 `*.pdf` 与 `*.md`）或 `archive`（打包 tar.gz 单文件上传），云端可直接预览白名单内的原文件、无需解压；
- **一次授权、终身使用**：首次使用某个端点先走授权（拿凭证 → 验证 → 保存凭证位置与使用方法到端点注册表），之后用户说「备份」直接凭证登录上传，不再打扰用户；
- **默认全端冗余**：用户说「备份」不指定端点时，同一份备份包上传到全部已注册端点，单端失败不影响其它端。

## 端点注册表

已授权端点登记在 `endpoints/endpoints.json`（本机数据，不随开源仓库分发），每条记录端点名称、类型、凭证位置与用法、详情文档路径、授权时间。注册新端点的完整流程见 `references/new-endpoint.md`。

## 结构

```
backup/
├── SKILL.md                  # 主文件：机制、四个动作、通用纪律
├── README.md                 # 本文件：动机与设计
├── endpoints/                # 本机端点数据（注册表 + 凭证文件），不入开源仓库
│   ├── README.md             # 目录说明（唯一入库文件）
│   └── endpoints.json        # 端点注册表（本机生成）
├── scripts/
│   └── backup.sh             # 备份入口：打包一次、逐端上传
└── references/
    ├── feishu.md             # 飞书端点详情（认证、坑、查看恢复命令）
    └── new-endpoint.md       # 注册新端点（首次授权）流程
```
